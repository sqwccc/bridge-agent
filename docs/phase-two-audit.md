# 对接 FAQ 第二期核查与实现

日期：2026-10-26。来源是 `.env.local` 已配置的独立测试库 `bridgemind_test`，来源 schema 为 `qiaoliang`。先执行只读字段和数据核查，再实施接口、前端及验证。没有修改源表、同步来源或补造监测值。

标准依据为 `历史资料/省市数据对接FAQ.xlsx` 的「省桥梁结构」「基础结构」「实时监测指标」及 FAQ 阈值说明。任务附件还核对了历史字段清单中 `rwid`（任务 ID）、`fid` 和 `ql_sys_file.p_id`（业务主键）的说明，实际关联以数据库精确匹配结果为准。

新增跨径、养护类别、使用状态、三特类型分布；分类缺失仍计入底数。三特多选筛选采用“任一匹配”，如 `specialTypes=1,2` 返回 143 座。列表、大屏、地图、告警复用同一筛选 SQL。

关联使用最新有效测点、最新未删除设备、同地市的设备标识及精确指标。核查中阈值 `SBBSM` 有 7,161 行匹配设备 BSM，匹配设备 YSKZJBZ 的行数为 0；采用已经证实的 BSM 关系，不猜测别名。只有能唯一确认桥梁归属的数据进入接口。

新增 `/bridges/{id}/monitoring/thresholds`，每条来源记录独立返回，不把同一级别压成一个上下限。保留缺失、倒置、历史表达、占位极值和来源同步时间；不自行判断边界是否包含，不用这些区间重新生成报警。曲线可选择显示有效结构化上下限参考线；极值占位和倒置区间不用于参考线。

39 个桥梁监测指标的名称和单位直接从 Excel「实时监测指标」提取并随版本保存到 `backend/src/main/resources/reference/bridge-metrics.tsv`。响应注明 `unitBasis=FAQ_2026`。未知指标单位为空，不按设备名称猜测，也不转换不同单位。例如 QL2501 保留字典中的 `cm/s/s`。测点还返回设备类型、型号、原始状态编码和设备同步时间；状态编码不被自动解释成在线。

## 检测记录和附件归属

| 来源表 | 原始行数 / 唯一键数 | 处理 |
|---|---|---|
| dwd_ql_jg_dqjc_all | 8,834 / 8,831 | 先选最新版本再排除删除，同地市唯一桥梁关系 |
| dwd_ql_jg_cgdj_inc | 40,316 / 40,316 | 以桥梁 ID 和地市关联，30,515 条明确关联有效桥梁 |
| dwd_ql_js_fjxxb_inc | 75,007 / 75,007 | 独立附件及任务附件分别处理，最新版本改变父对象时不恢复旧归属 |
| ql_sys_file | 18 / 18 | 核对业务主键与定检任务 ID，任务共享范围单独返回 |

`附件信息.fid = 定检记录.id` 当前匹配 0 条，因此本桥定检记录没有可确认的独立附件索引。进一步核查发现：

- `附件信息.fid = 定检记录.rwid` 匹配 684 个文件、412 个任务，涉及 5,027 个来源桥梁 ID；23,908 是文件与定检记录的关联行数，不能当作独立报告数量。
- `ql_sys_file.p_id = 定检记录.rwid` 匹配 2 个文件、1 个任务、51 个来源桥梁 ID；102 是关联行数。
- 这些汇总是源表精确匹配数量；接口中的 `relatedBridgeCount` 另按当前最新记录和有效桥梁范围去重计算。

接口将任务文件标为 `attachmentScope=TASK`，返回任务 ID 和涉及桥梁数；它们不是每座桥独立上传的检测报告。只有当前桥梁存在对应任务关系时才能在该桥上下文读取，任务变更和附件改挂均按最新版本判断。单桥附件使用 `BRIDGE` 范围。

定检表 `ZT` 存在 NULL、空字符串、数字和业务描述，附件表状态也未提供可靠删除字典；不把这些值擅自当作逻辑删除。同步表的 SJTBZT 删除仍严格执行。

底数 `FJ` 非空共 1,075 座，其中 266 个是空 JSON 数组 `[]`，不计为图片附件；其余 809 座为普通来源值，其中还有非地址文字。服务支持单地址、JSON 数组及明确的 URL 列表；不按文件名中的普通逗号盲拆，不把说明文字或数字当作可访问 URL。原始地址只留在服务端。

报告接口保留数组结构，增加来源、检测类型、记录标识、检测时间、同步时间、提供条件、共享范围及附件类别。底数即使没有报告地址，也返回“报告提供情况”，说明允许为空、应提供但缺失或无法判断；不会冒充真实检测文件。检测记录缺少独立附件时明确说明，共享任务文件另列。

文件状态分开处理：元数据未提供、条件允许为空、来源未配置、地址格式不支持，以及实际读取失败。读取失败不改写来源“已提供附件”的事实。PDF 和 PNG/JPEG/GIF/WebP 通过受保护的同源接口预览，按内容头校验类型；不绕过原有来源地址限制、禁止重定向和大小限制。

## 验证与剩余数据条件

只读审计工具：`python scripts/audit-phase-two.py`，完整输出为 `runtime/phase-two-audit.json`。

PostgreSQL 集成测试包括档案真实字段、多选和范围统计、阈值桥梁归属、同级多区间、最新删除，以及报告跨市、附件改挂和共享任务涉及多桥。测试边界数据使用 SELECT 内 CTE，不建测试表，不写来源数据。文件读取使用隔离的本机 HTTP 服务和浏览器拦截验证。

监测值来源仍为空，真实连续曲线无法从现有数据验证；附件服务地址尚未配置，真实历史文件是否可读尚不能确认。功能和失败状态已实现，页面保留真实空态，不显示模拟曲线或假附件。巡检、病害、维修业务接口属于第三期，本期没有扩大到写入处置流程。
