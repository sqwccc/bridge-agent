阈值表共 2734 行，其中 2386 行不匹配本文件万福大桥设备与指标，不导入。测点的设施编号、设备的测点编号及实测记录的设备/指标均在写入前校验。地市代码依据桥梁档案和实测记录补齐为 321000，区县代码保持原值。

元数据表 `tbsj` 映射到 `sjtbsj`；设备 `azrq` 映射到 `azsj`；实测表 `tbsj` 保持原字段。原始提取日期及 Kafka 字段未写入不具备这些字段的目标表，完整原始内容保存在本地 `runtime/wanfu-source.json` 中。

部分阈值的 `bsm` 被不同级别复用。导入标识采用 `wanfu-` 加原始编号、设备、指标、级别、上下界组合的 SHA-256 前 32 位，原始 `yskzjbz` 保留，原始 `bsm` 可在提取文件追溯。缺失阈值上界或下界保持空值，不补造区间。

采集时间范围：2026-10-21 23:27:04 至 2026-10-22 23:59:48（沿用来源北京时间）。页面历史查询可选 2026-10-21 00:00 至 2026-10-23 00:00；设备选择中的 WFDQ 编号对应本批数据。

## 执行与核验

`scripts/import-wanfu-monitoring.py` 默认只核对，传入 `--apply` 才写入；仅允许指定测试库。使用单事务，既有同标识记录必须字段一致，否则回滚；一致记录跳过。原始 Excel 不修改。

本地提取、导入报告和校验脚本分别为 `runtime/wanfu-source.json`、`runtime/wanfu-import-report.json`、`runtime/verify-wanfu.py`。校验逐条比对 3000 条采集时间与数值，并检查 10 类指标的实际 API 序列。

## 曲线读取优化（2026-10-27）

监测服务按桥梁 ID 和城市缓存已校验的测点清单，最多 256 个缓存项，写入后 30 秒过期；同一缓存项并发加载合并，失败不缓存。桥梁可见性仍由 BridgeService 校验，测点/设备/指标必须匹配有效清单。曲线与阈值数值不在服务端缓存；元数据变更最多延迟一个缓存周期反映。

曲线快路径通过服务端取得的城市代码、测点、设备、指标与时间范围读取，避免重复计算全省归属。阈值先按城市及阈值标识选取最新版本，再匹配已校验的设备/指标，保留删除状态、空指标和同级多区间的原有语义。原查询保留用于只读一致性回归。

前端曲线缓存键仅使用序列标识与时间区间，不再因设备说明等元数据变化失效；曲线和阈值请求传递取消信号，切换后不继续等待已无订阅的旧请求。

同一环境、同一历史区间的少量请求实测（毫秒，非容量压测）：

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 测点列表，3 次重复请求中位数 | 1755.8 | 28.7 |
| 单序列，5 次请求中位数 | 3304.6 | 60.6 |
| 阈值，3 次请求中位数 | 4845.2 | 89.2 |
| 10 类序列、最多 3 并发完成时间 | 12402.1 | 185.1 |

上述优化后重复请求均在测点缓存有效期内；服务重启后首次测点加载仍为 3983.0 毫秒，冷加载/缓存过期时仍需重新执行归属查询。当前实测表共 3000 行，不代表长期高频数据容量结论。

验证：19 项相关单元测试通过；3 项 PostgreSQL 只读集成测试通过，包括万福大桥 10 类指标与全桥阈值的新旧结果一致，以及跨城市、设备、指标、时间、删除/迁移阈值边界。前端类型检查、定向 lint 和构建通过。复测数据保存于 `runtime/monitoring-performance.json`。
