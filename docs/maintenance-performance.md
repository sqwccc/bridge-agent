# 维修养护建议响应速度优化

2026年11月1日，在 `codex/agent-qa-enhancement` 分支完成。优化保留现有分类与回答模型、提示词、业务统计口径、三阶段建议、候选数量及来源引用。

## 实测结果

同一台机器、同一来源库、相同问题“维修养护建议”、自动模式、新会话，通过本机后端逐条测试。每个范围分别保存优化前、最终版首次查询、30秒内重复查询的完整SSE记录；均明确返回Dify模型回答，无规则降级。

| 范围 | 优化前完整回答 | 优化后首次完整回答 | 30秒内重复查询完整回答 |
|---|---:|---:|---:|
| 万福大桥 | 40.88秒 | 21.05秒 | 7.38秒 |
| 全网接入桥梁 | 44.70秒 | 22.17秒 | 7.78秒 |
| 通富大桥 | 40.06秒 | 20.67秒 | 7.67秒 |

首次完整回答缩短约48%至50%，缓存命中时缩短约81%至83%。这些是各场景本轮实测值，不是压测均值或服务时限承诺；数据库和模型负载变化会影响结果。

| 范围 | 优化前首段文字 | 优化后首次首段文字 | 缓存命中首段文字 |
|---|---:|---:|---:|
| 万福大桥 | 35.22秒 | 15.64秒 | 1.95秒 |
| 全网接入桥梁 | 37.25秒 | 14.83秒 | 1.70秒 |
| 通富大桥 | 35.13秒 | 14.91秒 | 2.02秒 |

万福的资料查询阶段由33.45秒降到12.81秒；重复请求中的证据返回在计时精度下接近即时。模型仍逐次生成完整建议，不复用旧回答文字。

## 实现

### 精简与合并查询

原路径分别执行三类业务的统计、样本查询，以及监测覆盖、养护分组、候选查询，共9次专用查询，此外还有档案和桥梁范围读取。优化后专用查询为4次：巡检、病害、维修各一次，以及监测覆盖一次。

每类业务复用原 `WorkMapper.base` 的来源最新版本、删除状态、桥梁归属规则及原筛选条件。一次筛选产生 `matched`，由同一批记录生成所需统计和最新3条样本；病害查询同时产生养护互斥分组与最多5条候选。统计不截断，样本和候选在SQL中限量，排序与原版一致。

只计算本主题使用的统计维度，不再生成用不到的地市、月份等维度后在Java中丢弃。原单业务问答仍可调用完整统计查询。

### 有界并行

四类独立查询由全局4个工作线程并行执行，为6连接的来源连接池保留容量。队列有上限；结果按固定业务顺序组装，避免完成顺序影响引用编号。任意任务失败不会返回半份证据，取消或失败会取消尚未完成的任务。

“整体数据情况”共用这条取数路径，因此也获得精简查询与并行取数；本次完整耗时对比针对“维修养护建议”。

### 短时缓存

仅对真实数据的养护方案证据增加缓存，不缓存模型回答或会话。缓存键包含完整执行计划、桥梁ID及北京时间日期，涵盖页面范围、业务起止日期和其他执行条件。

- 完整资料成功生成后最多缓存30秒，上限64组；相同条件的并发请求共用一次加载。
- 失败不缓存、过期重新读取；不同桥梁、全网范围与不同日期分别缓存。
- 每次返回独立副本，避免一个会话修改另一个会话的资料。
- 保留原始查询时间，在证据中记录资料整理完成时间及有效秒数；界面显示资料查询时间和“相同条件的资料最多复用30秒”。

缓存命中意味着复用最近一次查询资料，不代表重新读取数据库；来源变更可能在缓存过期后才反映。原有桥梁档案快照缓存仍按原机制工作。统计口径、来源版本选择及数据准确性校验保持原样。

## 2026-11-02 固定数据临时回答缓存

在原有 30 秒资料缓存之外，增加独立的完整养护模型回答缓存。默认关闭，通过本地 `.env.local` 的 `MAINTENANCE_ANSWER_CACHE_SECONDS=1800` 开启，最大有效期限制为 30 分钟；设为 0 并重启可关闭。内存最多 64 条，重启即清空，不修改 Dify 应用或来源数据。

缓存仅适用于 source 模式、增强问答、模型与分类器均已配置、自动模式的新对话首轮，且成功完成的执行计划为 business_query / maintenance_plan。键包含 HTTP 会话、完整问题原文、范围、桥梁、页面筛选、起止日期、回答模式及北京时间日期。不共享不同登录会话，不缓存规则降级、空回答、失败或中断；已有会话的追问继续正常处理。命中时复用原计划、正文、证据、引用和图表，建立当前新对话上下文，保留资料原始查询时间，并显示临时缓存说明。固定快照如被更新，应重启后端立即清空，否则最长 30 分钟后重新读取。

本地启用并重启后，真实 Dify 联调：同一浏览器会话条件下，万福大桥“维修养护建议”新对话首次完整响应 20.171 秒，随后新对话同题命中小于 0.1 秒。正文、证据（排除回答缓存说明）及图表完全一致。记录见 runtime/maintenance-answer-cache-benchmark.json。此结果为单轮本机接口实测，不含浏览器绘制或公网延迟。测试过程中模型故障降级未写入缓存。

相关后端测试 17 项通过，包括会话/桥梁/问题/日期隔离、超时过期、关闭开关、私有副本、命中跳过数据库及模型、追问继续调用模型、失败降级不缓存；前端构建通过。
