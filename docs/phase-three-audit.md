## 两种明确口径

单桥业务接口采用最新有效记录，分页总数与业务筛选共用同一查询；包含空业务日期的记录在未选择日期时仍保留。`issuesOnly=true` 使用与详情 `dataIssues` 一致的必需信息、编码和时间检查。

质量页的 `scope=RAW_IMPORT` 明确核查导入原始行，包含历史版本和删除行，不能替代最新有效业务总数。它展示原始行、有效标识组合、重复多出行、删除行、关联覆盖，以及缺失、编码、日期等问题。问题可能重叠，不相加为问题记录总数。“重复多出行”针对记录标识，不等于病害业务编号重复。

质量页的“业务关联核查”另用最新有效且可唯一归属的病害和维修记录，统计同市同桥重复病害编号及维修关联状态。汇总缓存 5 分钟并显示 checkedAt；原始问题列表单独分页。查询故障返回错误，不转换为 0 行。

## 交付与复核

- 页面：`/bridges/{id}/records?kind=patrols|defects|maintenance`，由单桥档案进入；日期、关键词、业务属性和待核查筛选保留在 URL，详情支持业务追溯和附件读取。
- 质量页：`/data-quality`，由大屏顶栏或业务记录页进入，可切换业务、地市及问题，能确认桥梁的记录提供追溯入口。
- 附件：复用第二期的同源限制、禁止重定向、大小和实际类型校验，详情读取失败不改变来源提供状态。
- 审计：`python scripts/audit-phase-three.py`，生成 `runtime/phase-three-audit.json` 和对应查询；复用应用 Mapper，不输出人员和原始附件地址。
- 可执行核查说明：`docs/phase-three-audit.ipynb`，展示表结构、汇总、查询与关联结果。
- 回归：后端规则及 PostgreSQL SELECT CTE 边界测试、前端构建/静态检查及浏览器接口、页面和附件测试。最终执行结果见 [验收记录](verification.md)。

性能处理：巡检表没有来源索引，保持只读。先按桥梁缩小候选主键，物化候选版本后排序，避免全表有序嵌套关联；版本复查使用城市和记录标识两个等值键。分页通过窗口计数一次返回记录与总数，只有超出末页的空页才补查总数。详情进一步限制记录标识，仍复查全部版本与最新归属。

最终预览冒烟中，258万行来源的巡检样桥分页约9.17秒，病害/维修约1–2秒、质量汇总约3.38秒；实际延迟还受远程数据库和并发影响。当前未调整来源索引，巡检查询性能仍需在后续运行规模下持续评估。

可持续维护的核查规则包括：记录标识完整性和唯一性、同市同桥关联覆盖、最新删除和改挂、枚举原值保留、缺失结果不推断正常、业务日期顺序和附件地址不外泄。来源只读，业务写入流程、健康评估、BIM 与真实连续监测仍按各自接入条件后续建设。
