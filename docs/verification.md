## 2026-10-27 大屏接口性能优化验证

同一本地后端、同一来源数据库、同一参数，分别串行请求三轮。优化前取三轮中位数；优化后分别记录服务启动后首轮与第二、三轮缓存命中，不能把缓存命中当作冷查询加速。

| 接口 | 优化前中位数 | 优化后首轮 | 优化后缓存命中 |
| --- | ---: | ---: | ---: |
| dashboard | 1855 ms | 2324 ms | 5–9 ms |
| dashboard/options | 1670 ms | 8 ms（复用前一请求的快照） | 3 ms |
| bridges?page=1&size=8 | 3434 ms | 14 ms（复用快照） | 4–5 ms |
| alarms?size=50 | 3530 ms | 1817 ms | 5 ms |
| dashboard?q=万福 | 1660 ms | 1694 ms | 3–4 ms |

字典接口维持毫秒级。六个接口的完整data载荷逐项比较相同，包括统计数、列表顺序、总数和地图点位，窗口计数字段没有泄露到JSON。记录：runtime/screen-benchmark-before.json、runtime/screen-benchmark-after.json；复测脚本：runtime/benchmark-screen.cjs。

浏览器使用相同1920×1080视口。暂停请求32秒后重新打开页面，首屏最慢业务接口从4245 ms降到1892 ms，约降低55%；地图点位均为115个。此指标为首屏请求中的最大接口耗时，不是整页渲染时间，也不是并发压测P95。桥梁清单关闭时不再发起bridges请求。原首屏统计、选项、桥梁列表/总数、报警列表/总数合计六次公共底数查询，现为桥梁快照一次、报警含窗口计数一次。记录：runtime/screen-performance-browser-before.json、runtime/screen-performance-browser-after-expiry.json。搜索阶段的导航计时不用于上述首屏结论。

验证通过：后端默认测试33项通过、9项来源库测试按原配置跳过；另显式运行新增ScreenPerformanceSourceTest，真实PostgreSQL只读验证筛选、分页、地市统计、报警窗口总数和越界空页一致性。新增单元测试覆盖缓存并发合并、30秒过期、失败重试及分页边界。前端构建通过，6项浏览器测试通过，覆盖搜索高亮、清单按需请求、分类筛选、刷新返回、设备桥梁范围和页面布局。
