## SQL 包全量副本

2026-10-23 全量导入完成：238 张表，共 18,099,498 行；其中 13 张原有来源表比对一致并保留，新增 225 张表，失败 0 张。本系统两张表内容校验未变。

完整导入工具为 `scripts/import-full-source.py`，对应 `docs/历史资料/sql/ql/1` 的 238 个 SQL 文件和 `docs/历史资料/sql/ql/2` 的字段元数据，仅写远程独立数据库 `bridgemind_test` 中的 `qiaoliang` schema。本系统账号表和 Flyway 表仍单独位于 `bridgemind_test` schema。

工具解析 INSERT 字面量，通过 COPY 流式导入；不执行文件中的任意 SQL。已有表先在临时表中重建包内数据，逐行比较（包含重复行次数），一致则保留原表，差异则报错，不覆盖或追加。新表逐表事务提交，失败回滚；再次运行会按文件 SHA-256 和行数跳过已完成表。结果及失败清单位于 `runtime/full-source-import.json`。

包内仅有数据 INSERT 和字段元数据，因此按所给字段重建结构，不推测未提供的主键、外键、默认值或触发器。geometry 字段延续测试副本方案，以 text 保留原始值，未启用 PostGIS 空间计算。四个外部二进制引用解析为本包 `files/` 下的对应 `.data` 文件；这些文件均为零字节，按空二进制值导入。

全量副本包含原系统用户、权限、登录记录和其他业务数据，仅作为来源资料存储，不复用原账号登录，也不自动接入现有大屏业务逻辑。下方映射说明仍仅覆盖本系统实际使用的功能。

## 已确认的数据缺口

- 来源底数 14,428 条，其中有效桥梁 14,372 条，桥梁 ID 无缺失和重复。
- 有效桥梁中可定位 14,130 座；其余仍参与统计和搜索。坐标问题包括缺失和越界，不能只用“非空”判断有效。
- 有效监测点 14,750 个，唯一关联 14,099 个，覆盖 406 座桥梁；可关联报警 704 条，时间范围为 2024-06-18 至 2025-11-21。
- 可唯一关联定检记录 8,711 条。底数中的检测报告路径 121 条，其中以 PDF 结尾的路径 44 条；路径存在不代表文件已可访问。
- 监测值表 `dwd_ql_jc_jcz_inc` 和 `ql_js_ssjc` 均为空。`dwd_ql_jc_jcz_sd_all` 是隧道来源，不导入桥梁曲线。
- 监测分析报告表 `ql_jc_sjfxbg` 为空，且其元数据缺少直接桥梁标识。当前展示的是明确关联的检测/定检报告，前端不会标成监测分析报告。
- 字典表 `dwd_ql_js_sjzd_inc` 为空。2026-10-26 已依据 FAQ 补充桥型、监测、BCI/BSI、养护类别、跨径、生命周期及档案字典；第二期新增39个桥梁监测指标的名称、单位，注明FAQ字典依据；第三期依据随包字段元数据补充病害和维修分类/状态字典。未知指标单位及报警处置状态的完整释义仍待提供。
- 有些测点/报警编码无法映射，或存在多候选。接口排除歧义关联，审计报告单独统计；不通过桥名匹配，也不随机挂到其他桥梁。
- 附件资料大多只有路径，实际文件服务地址和授权信息尚未提供。因此“有报告记录”不代表“附件可下载”。
- 部分建成年月包含原始异常月份（例如 `98`）；以来源文本展示，不强制转换日期。

## 更新与审计

运行 `python scripts/source-audit.py` 生成 `runtime/source-audit.json`，记录有效底数、坐标、测点关联覆盖率、歧义点位、可关联报警时间范围及报告数量。导入结果含源文件 SHA-256，位于 `runtime/import-report.json`。

2026-10-26 第一期新增核查、字段类型与数据基线见 [第一期核查](phase-one-audit.md)。`python scripts/audit-phase-one.py` 使用 `.env.local` 的实际来源连接执行只读审计；现有覆盖审计也已改为读取同一配置，并复用应用的公共查询规则。

第二期核查与最新关联规则见 [第二期核查](phase-two-audit.md)。`python scripts/audit-phase-two.py` 记录扩展字段覆盖、阈值质量、独立及共享任务附件的实际关系；共享附件关联行数不等于独立报告数量。

第三期字段、关联及质量证据见 [第三期核查](phase-three-audit.md)。`python scripts/audit-phase-three.py` 复用应用质量 Mapper，记录主键、字段完整性、原始关联覆盖、日期、重复病害编号及最新有效业务关联。巡检 jcjg 全空，不能解释为正常；252组同市同桥病害编号重复，不能将编号视为病害主键。补充养护表只有1行且不匹配有效桥梁，单独记录缺口。

本地导入不会覆盖非空表。新增资料需先核对字段及来源版本，再明确执行独立副本更新；不要将全目录 SQL 直接执行到业务库或真实来源库。
